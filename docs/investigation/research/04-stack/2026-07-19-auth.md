# Auth for sync-only accounts + PowerSync JWT contract — research brief

**Date:** 2026-07-19 · **Phase:** 4 (stack & platform fit) · **Author:** research subagent

**Verdict:** Embed better-auth (MIT, TS-native) in Koi's own write-path API against Koi's own Postgres; its JWT plugin exposes a JWKS endpoint self-hosted PowerSync consumes; skip email delivery entirely via passkey/password + recovery codes.

## Findings

**PowerSync JWT contract** (docs.powersync.com, 2026-07-19): `sub` = user ID, `aud` matches the instance (self-hosted: `client_auth.audience` in `powersync.yaml`), `iat`+`exp` required; `exp` ≤ 24 h, ≤ 60 min recommended. Asymmetric algs (RS/ES 256–512, EdDSA) recommended; HS256 supported but flagged dev/testing-only. Keys via `client_auth.jwks_uri` (refetched every few minutes; `kid` must match) or a static `jwks` block; client SDKs call your `fetchCredentials()` for tokens.

**better-auth** (better-auth.com docs + GitHub, 2026-07-19): v1.6.23 (2026-06-29), MIT. Framework-agnostic TS library — auth in your server, users in your DB, no third-party processor (privacy floor). Email+password is core. The JWT plugin serves JWKS at `/api/auth/jwks` (configurable), signs EdDSA/Ed25519 by default (ES256/RS256/PS256 available); audience, subject, payload, expiry all settable (default 15 min — inside PowerSync's 60-min recommendation); clients fetch tokens via `authClient.token()` / `GET /api/auth/token`. Passkey plugin (SimpleWebAuthn) covers registration, sign-in, conditional UI on web. `deleteUser` does a hard delete gated by password or fresh session (≤ 24 h) — maps to S-7. Official `@better-auth/expo` handles SecureStore cookies and deep links (docs target Expo SDK 55 / RN 0.83). Absorbed Auth.js 2025-09-22.

**Auth.js/NextAuth v5**: maintenance-only since the merger 2025-09-22; in beta since Oct 2023, never stable (npm `latest` still 4.x); maintainers point new projects to better-auth. Refuse. **Lucia**: v3 deprecated Mar 2025; now a learning resource (Oslo/Arctic live on). Not a candidate. **Hand-rolled** (argon2 + jose): feasible, but you own hashing policy, session rotation, WebAuthn ceremonies, and timing-attack hygiene forever — negative-value at 10 h/wk; D-022 cuts against it. **Heavy IdPs** (2026-07): Keycloak baseline ~1,250 MB JVM RAM (keycloak.org sizing) blows the VPS headroom; Zitadel (512 MB–1 GB) is still a separate Go service for one tenant; Ory means multiple services. Refuse. **SaaS** (Clerk, Auth0): third-party processor of account data — violates the privacy floor. Refuse.

**Email**: single-tenancy makes verification theater — the only account is the owner's. Skip-email design: passkey + password + one-time recovery codes; deletion confirmed in-app with a fresh session. If ever wanted: Resend free tier 3,000/mo vs Postmark ~~100/mo trial~~ **corrected (review):** 100/mo non-expiring free dev plan (2026-07); self-hosted SMTP isn't worth it for resets.

**Passkey-first?** Yes, with password fallback: it deletes the reset-email dependency; RP ID = owner's sync domain; iCloud Keychain / Google Password Manager sync credentials across devices. Caveat: the passkey plugin is web-documented; native-app passkeys in Expo need a community module — unverified, spike in Phase 5.

**Integration sketch**: mount better-auth in the bespoke TS write-path API (same process, same Postgres); JWT plugin with `audience` = PowerSync instance URL, 15-min expiry, `sub` = user ID (the same ID `@koi/domain` write checks key on); `powersync.yaml` → `client_auth.jwks_uri: https://api.<owner-domain>/api/auth/jwks`; client `fetchCredentials()` = `authClient.token()`. Accounts are created only in the enable-sync flow; local-only never touches auth. S-7 = `deleteUser` + cascade of synced rows + PowerSync sync-rule cleanup.

## Numbers

- better-auth: v1.6.23 (2026-06-29); 29.2k GitHub stars (2026-07-19); **5,257,853 npm downloads** wk 2026-07-12→18 (api.npmjs.org) vs next-auth 4,697,730; MIT; ~~Better Auth Inc., YC S25~~ **corrected (review):** YC X25 (Spring 2025), $5M seed (Peak XV, YC, P1 Ventures, Chapter One), **acquired by Vercel 2026-07-07**; frequent 1.6.x patch cadence.
- Keycloak: ~1,250 MB RAM baseline per pod; Zitadel: 512 MB–1 GB min (both 2026-07).

## Risks

- better-auth is young (v1.x since 2024) and ~~VC-funded: open-core drift~~ **corrected (review):** Vercel-owned since 2026-07-07 (pledged open source, framework-agnostic): platform-first drift or breaking-change churn possible. Mitigation/exit: schema is plain Postgres tables in Koi's DB; swap cost is a rewrite of one auth module, not a data migration.
- JWT signing keypair lives in the DB — same backup story; losing it invalidates sessions (annoying, not fatal).
- Recovery-code loss locks the account — mitigated: the owner has DB access and can reset out-of-band.
- Expo native passkeys unverified; if the spike fails, launch password-first on mobile, passkey on web.
- Solo dev must watch better-auth security advisories himself.

## Koi fit

Privacy: excellent — self-hosted, own DB, zero processors. Invariant preservation: neutral — auth is orthogonal; `sub` feeds the server write path cleanly. Offline depth: excellent — accounts exist only when sync is on; local-only needs no auth code. Solo maintainability: high — one TS library in a process you already run; hand-rolling and heavy IdPs refused here. Cost: EUR 0 incremental. Maturity (D-022): satisfied — 5.3M weekly downloads, 29k stars, Vercel-backed steward; youth risk covered by the exit plan. **Recommendation: better-auth + JWT plugin → PowerSync JWKS; passkey-primary, password fallback, recovery codes, no email dependency.**

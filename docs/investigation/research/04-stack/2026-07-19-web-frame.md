# Web companion frame: Next.js vs Vite SPA/PWA vs TanStack Start — research brief

**Date:** 2026-07-19 · **Phase:** 4 (stack & platform fit) · **Author:** research subagent

**Verdict:** Build the web companion as a Vite + React SPA (static files behind Caddy) with a client-side router; Next.js is overkill for a 100%-client-rendered, sync-required app, and TanStack Start's server layer is dead weight here.

## Findings

**PowerSync Web SDK.** `@powersync/web` 1.39.0, stable 1.x; peer deps `@journeyapps/wa-sqlite ^1.5.0`, `@powersync/common ^1.57.2` (npm, 2026-07-19). No beta flags in docs; the May-2026 blog treats it as production guidance. VFS: `OPFSCoopSyncVFS` recommended (multi-tab on Chrome/Firefox/Safari incl. iOS, fine past 1 GB); `IDBBatchAtomicVFS` fallback (no OPFS in Safari incognito; IndexedDB degrades >100 MB); `OPFSWriteAheadVFS` (Apr 2026) Chromium-only. SharedWorkers cannot open OPFS sync handles, so multi-tab runs on dedicated workers + Web Locks — bundler/worker config is the fiddly part. No COOP/COEP headers needed (wa-sqlite VFSes use access-handle pooling, unlike official sqlite-wasm), so plain Caddy static hosting suffices (powersync.com blog May 2026; docs, 2026-07-19).

**Safari ITP eviction.** Safari deletes all script-writable storage (IndexedDB, OPFS bucket, service workers, localStorage) after ~~7 days without user interaction with the site~~ **corrected (review):** 7 days *of Safari use* without site interaction (Safari 13.1+; webkit blog 10218 / MDN, 2026-07-19). Home-screen-installed PWAs are exempt. At rung 3 the whole DB is re-syncable, so eviction costs a re-login (token evicted too) plus a re-download — annoyance, not data loss. Narrow edge: an offline web edit, tab abandoned >7 days before upload, is lost. Acceptable for a companion; mitigations: home-screen install, eager upload.

**Candidates.**
- **Next.js App Router** — v16.2.10; Next 16 shipped 2025-10-21 (Turbopack default) (nextjs.org blog, 2026-07-19). Architected around RSC/SSR; a pure client-side wasm/worker/OPFS app fights it (`'use client'` everywhere, SSR-unsafe import guards). `output: 'export'` disables middleware, server actions, ISR, image optimization, request-time handlers — the constraints without the value (static-export guide, 2026-07-19).
- **Vite + React SPA** — Vite 8.1.5; Vite 8 stable 2026-03-12, Rolldown bundler default (vite.dev blog, 2026-07-19). Pure client rendering matches PowerSync exactly; PWA installability via vite-plugin-pwa (standard Workbox wrapper; 3.8M weekly downloads, v1.3.0, npm 2026-07-20).
- **TanStack Start** — `@tanstack/react-start` 1.168.30 ~~(version line shared with Router)~~ **corrected (review):** no longer version-locked to Router (1.168.32 vs 1.170.18, npm 2026-07-20). v1 RC announced 2025-09-23; docs still badge it "RC" (tanstack.com, 2026-07-20). SSR-by-default full-stack with server functions Koi doesn't need; **TanStack Router alone** (client-first, type-safe) is the useful piece, usable inside a plain Vite SPA.
- **React Router / Remix** — RR v8 released 2026-06-17 (ESM-only, Node 22.22+, yearly majors, RSC still unstable); Remix 3 has pivoted to a separate non-React-meta-framework direction (remix.run blog, 2026-07-19). Framework mode has an `ssr:false` SPA mode (~~open issue #14268 flags PWA friction~~ **corrected (review):** closed completed 2025-09-01); declarative mode inside Vite is the simple path.

**Deployment on the VPS.** Vite SPA: `vite build` → static `dist/`, Caddy `file_server` + SPA fallback, zero runtime process, EUR 0 added. Next.js: either a Node process to babysit (`next start`) or the crippled static export. TanStack Start: Node/Bun server by default, SPA/prerender possible. RR framework mode: same shape as Start.

## Risks

- Safari ITP eviction → periodic re-login/re-sync in browser-tab usage; rare unsynced-write loss (see above).
- wa-sqlite worker/wasm bundling is the most fragile integration point; test multi-tab on real Safari early.
- Vite 8/Rolldown is only 4 months old (2026-03-12); residual plugin churn possible.
- TanStack Router's community is the smallest here (14.8k stars, D-022 concern); exit plan is cheap — swap routers inside the same SPA shell.
- SPA service-worker update staleness (classic PWA gotcha) needs an update-prompt pattern.

## Koi fit

Privacy: all candidates equal (static files, no trackers). Invariants/offline: frame-agnostic — PowerSync + `@koi/domain` run client-side regardless. Solo maintainability + cost: Vite SPA wins outright — no server process, no RSC mental model, one static folder behind Caddy. Maturity (D-022): Vite is the most popular tool in the comparison. **Next.js is refused, not deferred: the learning bias is a tiebreaker only, and this isn't a tie.** TanStack Start refused for the same reason (server layer without a job). Recommendation: Vite + React SPA + TanStack Router (justified: type safety, 20M weekly downloads; fallback React Router declarative) + vite-plugin-pwa.

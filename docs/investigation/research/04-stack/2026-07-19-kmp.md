# Kotlin Multiplatform / Compose Multiplatform — adopt or refuse — research brief

**Date:** 2026-07-19 · **Phase:** 4 (stack & platform fit) · **Author:** research subagent

**Verdict:** REFUSE — KMP/Compose is genuinely mature and healthy in 2026, but it is the wrong-language stack for a TS-strong solo dev whose locked plan centers on a pure-TS `@koi/domain` shared with a TS server; adopting it re-creates the Swift embedding problem in Kotlin while adding the largest learning bill of any candidate.

## Findings

- **iOS stability:** Compose Multiplatform for iOS has been **stable since 1.8.0 (2025-05-06)** per JetBrains (as of 2026-07-19). Since then: 1.9.0 (Sept 2025, web to Beta), 1.10.0 (Jan 2026, unified `@Preview`, Navigation 3, stable Hot Reload), 1.11.0 (~~2026-05-15~~ **corrected (review):** 2026-05-13, experimental UIView-backed native text input on iOS, concurrent rendering on by default). Latest stable **1.11.1 (2026-06-02)**; 1.12.0 in beta (as of 2026-07-19). KMP (shared logic) has been stable since Nov 2023. Kotlin **2.4.0 (June 2026)** promotes Swift export to **Alpha** and adds Swift-package dependencies; default iOS minimum raised to 15.
- **Adoption:** real and growing. Compose-MP-UI-on-iOS in production: Respawn (96% shared code), Markaz, Wrike, Feres, Physics Wallah (JetBrains 1.8.0 post, as of 2025-05). KMP-logic-with-native-UI: Google Docs iOS, Duolingo, Netflix, McDonald's, Forbes (kotlinlang case studies, as of 2026-07-19). A 2025 survey cited by secondary sources puts KMP usage at ~18% of respondents, up from ~7% — unverified against the primary survey.
- **PowerSync KMP SDK:** exists, active, past 1.0 — **v1.13.0 (2026-06-08)**; targets Android/JVM/iOS/macOS/tvOS/watchOS; Room integration still beta; ~~a CocoaPods-EOL migration for its SQLite extension is pending late 2026~~ **corrected (review):** already shipped — v1.12.0 links the SQLite core extension directly, no CocoaPod needed (CHANGELOG, 2026-07-19). It is the least-adopted PowerSync client SDK (~120 GitHub stars, 25 releases). The exact 1.0 GA date could not be verified (announcement page 404s).
- **The language conflict (decisive):** the LOCKED plan = TS server + pure-TS `@koi/domain` running client-side and server-side. Under KMP either (a) the domain is rewritten in Kotlin — the TS server then can't run it natively (Kotlin/JS export exists but makes the crown jewel a compiled artifact in its own toolchain, relitigating a locked decision), or (b) the domain stays TS and every Kotlin client embeds a JS engine — exactly the Swift-embedding problem this stack was supposed to dissolve, now in a language the dev doesn't know. No configuration removes work; every one adds Kotlin + Gradle + Compose idioms + Xcode integration on top of existing TS and Swift knowledge — plausibly 3–6 months of a 10 h/week budget before feature work resumes.
- **Quality bar:** Compose MP renders via Skia with Material 3 defaults. VoiceOver/AssistiveTouch/Full Keyboard Access are first-class and system font scaling is respected (JetBrains, as of 2025-05; Dynamic Type issue #2567 closed) — but iOS-native **sheet detents, zoom transitions, and rich haptics are not framework primitives**: they require UIKit/SwiftUI interop or third-party rebuilds, with recurring friction bugs (e.g. YouTrack CMP-9938, Compose scroll stalls inside native iOS sheet presentation — ~~open as of 2026-07-19~~ **corrected (review):** Fixed ~2026-03). The alternative route — KMP logic + native SwiftUI UI — preserves the bar but means writing SwiftUI *and* Kotlin: the worst combination for this dev.

## Numbers

- Compose Multiplatform: 1.11.1 stable (2026-06-02); **19.2k GitHub stars** (2026-07-19); backed by JetBrains; ~~2 minor releases/year~~ **corrected (review):** ~3 minor releases/year (1.8→1.11 in 12 months) + patches. Kotlin 2.4.0 (June 2026), 2.4.20-Beta1 (2026-06-24).
- PowerSync Kotlin SDK: v1.13.0 (2026-06-08); **~120 stars**, 25 releases, 581 commits (2026-07-19); vendor-maintained (PowerSync/JourneyApps). npm downloads: N/A (Maven Central; no public stats verified).

## Risks

- Kotlin + Gradle + Compose learning curve consumes the entire hobby-time budget for months; Gradle upkeep is a recurring tax.
- Domain logic forks or gains a compile-toolchain dependency; invariant parity between server (TS) and clients degrades.
- iOS polish (detents, haptics, transitions) lives in interop shims — the least-documented, most breakage-prone layer.
- Least-used PowerSync SDK → thinnest community when sync bugs hit (violates D-022's popularity preference in context).

## Koi fit

Privacy fit: neutral (self-hosted either way). **Invariant preservation: fails** — no clean home for a shared TS domain. Offline depth: fine (SQLite + PowerSync). **Solo maintainability: fails hard** for a TS-strong, zero-Kotlin dev. Cost: neutral. Maturity: KMP itself passes D-022; the *fit* does not. **Refuse; do not revisit unless the TS-domain decision is itself reopened.**

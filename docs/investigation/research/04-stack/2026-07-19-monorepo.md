# Monorepo tooling: pnpm workspaces, Turborepo, Nx — and the Expo gotchas — research brief

**Date:** 2026-07-19 · **Phase:** 4 (stack & platform fit) · **Author:** research subagent

**Verdict:** pnpm workspaces plus a thin Turborepo layer (local cache only, telemetry off); refuse Nx; ship `@koi/domain` as a plain tsc-compiled package so Metro, Vite and Node all consume the same dist.

## Findings

**Layers.** pnpm workspaces is the base: it declares the ~5 packages (`@koi/domain`, app, web, server, i18n/config) and links them via `workspace:*`. Turborepo/Nx only add task orchestration + caching. `pnpm -r run build` already runs topologically, but with no caching and no cross-package watch.

**Popularity & ownership (as-of 2026-07-19, npm registry + GitHub API).** pnpm 11.15.0 (pub. 2026-07-18), ~126M weekly downloads — a de-facto default. Turborepo: Vercel-owned; turbo 2.10.5 (pub. 2026-07-13), ~17.5M weekly downloads, 30.7k stars; ~~2.9 shipped 2026-06-24~~ **corrected (review):** 2.9 shipped 2026-03-30; 2026-06-24 is 2.10.0's npm publish date. Nx: Nx Inc (ex-Nrwl), $24.6M VC (seed 2022 + ~$16M Series A, Sept 2023, TechCrunch); nx 23.1.0 (pub. 2026-07-13), ~9.4M weekly downloads, 29.1k stars; majors every 6 months with `nx migrate` ceremony (nx.dev/docs/reference/releases).

**Config burden.** Turborepo for this repo is one ~15-line `turbo.json` (`dependsOn: ["^build"]`) plus `turbo watch`. Nx adds a daemon, inference plugins, generators and scheduled majors — power a 5-package repo never uses. Remote caching (both tools' headline feature) is irrelevant for one dev on one machine; the local cache is the whole win. Two Nx trust dents under D-022: self-hosted remote caching moved behind a Powerpack license in 2024 (community "rug pull", GH issue #28150), and the s1ngularity supply-chain attack (2025-08-26) — malicious nx versions live on npm ~4h, 1,700+ users' secrets leaked (Nx postmortem; Wiz). Nx remediated (trusted publishing), but it still counts. No comparable published incident found for turbo or pnpm.

**Expo/Metro in a pnpm monorepo, as-of 2026-07-19 (docs.expo.dev/guides/monorepos).** Now genuinely smooth: `expo/metro-config` auto-configures monorepos since SDK 52; Metro resolves pnpm symlinks out of the box on SDK 53+; pnpm's default isolated node_modules is supported since SDK 54 (the old `node-linker=hoisted` workaround is no longer needed); SDK 55 enables `autolinkingModuleResolution` by default for monorepo apps; expo-doctor and `expo-modules-autolinking verify` flag duplicate native modules. Current stable: SDK 57 (expo 57.0.7, pub. 2026-07-17). Remaining real footgun: duplicate react/react-native versions in the workspace are unsupported and break native builds — pin one version via pnpm catalogs.

**Sharing `@koi/domain`.** (a) JIT/source export (`"exports": "./src/index.ts"`): zero config in Metro and Vite; Node 24 runs it too — verified locally 2026-07-19 on node v24.16.0: type stripping (stable since 24.12.0, nodejs.org) works through the workspace symlink because resolution uses the realpath, so the node_modules restriction doesn't bite. But it restricts domain code to erasable syntax, and a tsc-built server (NestJS default) won't compile another package's TS. (b) tsup dist: works; dual-format bundling a private ESM-only package doesn't need — Turborepo's own docs recommend plain tsc for internal libs. (c) Plain tsc + project references/declaration maps: ordinary JS + d.ts to every consumer, go-to-definition lands in source, turbo caches the build, `turbo watch` rebuilds on save. **Least friction in 2026: (c).**

**Recommendation.** pnpm workspaces + Turborepo, local cache only, `turbo telemetry disable` on day one (anonymous usage telemetry is on by default — turborepo.dev/docs/telemetry). Exit plan per D-022: Turborepo is a deletable veneer — drop turbo.json and fall back to `pnpm -r` scripts in an afternoon.

## Risks

- Stale turbo cache masking a broken build if `inputs`/`outputs` are wrong; keep the graph tiny, use `--force` when in doubt.
- Vercel could deprioritize Turborepo; exit is an afternoon (above) — acceptable.
- Compiled `@koi/domain` puts a build step between editing an invariant and seeing it in the app; `turbo watch` must actually be running.
- Expo isolated-deps support is only ~2 SDKs old (54+, Sept 2025); odd native modules can still hit resolution bugs — expo-doctor first; hoisted fallback still exists.
- Forgetting the single react/react-native catalog pin breaks native builds confusingly.

## Koi fit

Privacy: clean once turbo telemetry is disabled; all tooling runs locally (Nx structurally nudges toward Nx Cloud — misaligned). Invariant preservation: one tsc-compiled `@koi/domain` artifact consumed byte-identically by Metro, Vite and Node is the strongest same-rules-everywhere guarantee. Offline depth: n/a. Solo maintainability: pnpm+turbo is ~20 lines of config; Nx fails this criterion outright at 5 packages. Cost: EUR 0. Maturity (D-022): pnpm and Turborepo are mainstream, corporately backed, huge community — nothing niche; Nx is equally popular but refused on need and trust record, not maturity.
